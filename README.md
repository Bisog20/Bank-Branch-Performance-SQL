# Bank Branch and Product Performance Analysis (SQL Server)

An end-to-end analysis built entirely in T-SQL (SQL Server Management Studio): schema design, data loading, quality checks, aggregations, window functions, target-vs-actual analysis, and a reusable reporting layer of views.

## Business questions

1. Which branches generate the most revenue, and how has it changed month to month?
2. How do deposits and loan volumes compare by branch and product?
3. Which branches are above or below their monthly targets?
4. What is each branch's running (year-to-date) total for deposits and revenue?
5. Which products contribute most to each branch's revenue?
6. Which branches have the weakest loan-to-deposit ratio?

## Data model

| Table | Type | Description |
|---|---|---|
| `Branch` | Dimension | 8 branches with region and open date |
| `Product` | Dimension | 6 products (3 deposit, 2 loan, 1 fee/service) |
| `BranchPerformance` | Fact | Monthly deposits, loans, and revenue per branch and product (24 months) |
| `BranchTarget` | Target | Monthly revenue target per branch |

## How to run

Run the scripts in `sql/` in order, in SSMS (SQL Server 2016 SP1 or later):

| Script | Purpose |
|---|---|
| `01_create_schema.sql` | Create the database and tables |
| `02_load_data.sql` | Load synthetic sample data (run once only) |
| `03_data_quality_checks.sql` | Duplicates, coverage, orphans, date range |
| `04_branch_product_summaries.sql` | Branch scorecard, product mix, YoY growth |
| `05_window_functions.sql` | Running totals, MoM change, moving average, rankings |
| `06_target_vs_actual.sql` | Variance, achievement %, and status vs targets |
| `07_reporting_views.sql` | Four views ready for Power BI or Excel |

Expected row counts after loading: Branch 8, Product 6, BranchPerformance 1,152, BranchTarget 192.

## SQL techniques used

CTEs, window functions (`SUM() OVER`, `LAG`, `RANK`, moving averages with explicit `ROWS` frames), conditional aggregation, `CROSS APPLY`, recursive CTE for date generation, `NULLIF` for safe division, and views as a reporting layer.

## Data note

All data is synthetic, generated by the loading script. Branch rankings, product revenue shares, and target attainment reflect how the sample was generated and should not be read as real-world findings. Deposits and loans are treated as monthly flows rather than month-end balances.
